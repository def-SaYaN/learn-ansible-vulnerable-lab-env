The two tabs above show what happens. This tab shows the how: the API/connection sequences that make it work, so you can trace the flow at a granular level.

③ One Ansible Windows task — module → PowerShell → WinRM → JSON result

Control node
(ansible)
Windows host
(WinRM 5985)
▶NTLM negotiate/auth (message-level encryption)
▶compile module (e.g. microsoft.ad.user) → PowerShell payload
▶WSMan Create Shell + Command, ship payload
◀module checks state → acts only if drift → JSON {changed:bool}

Idempotence lives in the module: it reads current state first and reports changed=false if already correct. That's why site.yml and reset.yml are safe to re-run. Reboots (promote/join) are handled by the collection: it triggers the reboot, waits, and re-establishes WinRM before the next task.
