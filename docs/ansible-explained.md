# Ansible, explained line by line (this project)

A teaching companion to the code. It walks the whole Ansible side of the lab in
execution order and explains what every file, task, module, and keyword does,
so you can read the project and actually learn Ansible rather than just run it.

This assumes Job 1 (Terraform) already created the VMs and wrote
`inventory/hosts.ini`. From here on it is all Ansible.

Security note: a few roles plant deliberate weaknesses. Here we explain the
**Ansible mechanics** of those tasks (which module, what it runs, how
idempotency is decided). The security "why" and how to exploit them lives in
[`attack-chains.md`](attack-chains.md) and [`ad-security-guide.md`](ad-security-guide.md).

## 1. The execution model in one page

Learn these seven words and the rest is detail:

- **Inventory** — the list of hosts and the groups they belong to.
- **Playbook** — a YAML file containing one or more plays.
- **Play** — maps a group of hosts to a list of tasks/roles (`hosts:` + `roles:`/`tasks:`).
- **Role** — a reusable bundle of tasks + variables + templates in a fixed folder layout.
- **Task** — one call to a module.
- **Module** — the unit of work (e.g. `win_feature`, `microsoft.ad.user`). Ships to the host, runs, returns JSON.
- **Handler** — a special task triggered by `notify:`, run once at the end of a play.

The engine, per task, per host:

1. Render `{{ Jinja }}` in the task's arguments using that host's variables.
2. Ship the module to the host (PowerShell over WinRM for Windows; Python over SSH for Linux).
3. Run it. The module checks current state and only changes what's needed (**idempotency**).
4. Return JSON: `changed`, `failed`, plus module data.
5. Mark the task `ok` / `changed` / `failed`, then move on.

The default **linear strategy** keeps all hosts in lockstep: every host finishes
task N before any host starts task N+1. `forks` controls how many hosts run in
parallel.

## 2. `ansible.cfg` — the settings

Ansible reads this from the current directory at startup. Line by line:

```ini
[defaults]
inventory            = inventory/hosts.ini   # default inventory, so you can omit -i
roles_path           = roles                 # where roles/ live
collections_path     = collections:~/.ansible/collections  # where installed collections are found
host_key_checking    = False                 # don't prompt on unknown SSH host keys (lab convenience)
retry_files_enabled  = False                 # don't litter *.retry files on failure
stdout_callback      = yaml                   # pretty, readable task output
bin_ansible_callbacks = True                  # let callbacks work for ad-hoc `ansible` too
interpreter_python   = auto_silent            # auto-find Python on Linux, no warning
timeout              = 60                      # connection timeout (seconds)
forks                = 8                        # up to 8 hosts in parallel
display_skipped_hosts = False                  # hide skipped tasks (less noise)
nocows               = True                     # disable the cowsay banner
```

```ini
[persistent_connection]
connect_timeout      = 60    # WinRM/SSH persistent connection setup timeout
command_timeout      = 90    # max seconds to wait for a single remote command
```

```ini
[ssh_connection]
pipelining           = True   # fewer SSH round-trips per task (faster); affects Linux pivot
ssh_args             = -o ControlMaster=auto -o ControlPersist=60s -o UserKnownHostsFile=/dev/null -o StrictHostKeyChecking=no
```

The `ssh_args` reuse one SSH connection for many tasks (`ControlMaster`) and
skip host-key prompts, which matters for the Linux pivot whose IP changes.

## 3. The inventory — who to talk to

`inventory/hosts.ini` is generated by Terraform, but the shape
(`inventory/hosts.ini.example`) is what Ansible parses:

```ini
[domain_controllers]
dc01 ansible_host=<dc01_public_ip>     # 'dc01' is an alias; ansible_host is where to connect

[domain_members]
srv01 ansible_host=<srv01_public_ip>
ws01  ansible_host=<ws01_public_ip>

[linux_pivot]
pivot ansible_host=<pivot_public_ip> ansible_connection=ssh ansible_user=ubuntu

[windows:children]      # a group made of other groups
domain_controllers
domain_members

[lab:children]          # everything
windows
linux_pivot
```

Key ideas:

- Each line under a `[group]` is a host. `dc01` is just a label; `ansible_host`
  is the real address (a public IP here). This is why the domain still uses
  private IPs (`10.10.10.10`) internally while Ansible connects over the public
  one.
- `[windows:children]` builds a parent group from child groups. So `dc01` is in
  `domain_controllers`, `windows`, `lab`, and the implicit `all`.
- Host-level vars can be set inline (like `ansible_user=ubuntu` on the pivot),
  but most vars come from `group_vars` (next section).

## 4. `group_vars` — variables per group

For each host, Ansible loads `inventory/group_vars/<group>.yml` for every group
that host is in, then merges them (more specific group wins). Role `defaults/`
are the lowest precedence, so anything here overrides a role default.

### `group_vars/windows.yml` (applies to the `windows` group)

```yaml
ansible_connection: winrm                 # use WinRM, not SSH
ansible_port: 5985                        # WinRM HTTP port
ansible_winrm_transport: ntlm             # NTLM auth (gives message-level encryption)
ansible_winrm_scheme: http                # http scheme (encryption is at the NTLM layer)
ansible_winrm_server_cert_validation: ignore  # don't validate TLS (lab)
ansible_user: Administrator               # log in as local Administrator
ansible_password: "Passw0rd!Admin#2026"   # must equal Terraform's admin_password
```

Then the domain identity, used by many roles via `{{ ... }}`:

```yaml
lab_domain_name: "vuln.local"             # DNS domain
lab_domain_netbios: "VULN"                # NetBIOS/short name
lab_domain_dn: "DC=vuln,DC=local"         # LDAP distinguished name of the domain
lab_forest_mode: "WinThreshold"           # forest/domain functional level
lab_safe_mode_password: "SafeMode#Restore1"  # DSRM password set during promotion
lab_domain_admin_user: "VULN\\Administrator"  # domain admin (post-promotion)
lab_domain_admin_password: "Passw0rd!Admin#2026"
lab_dns_server: "10.10.10.10"             # members point DNS here (the DC, private IP)
flag_prefix: "FLAG"
```

Why `Administrator` works before and after promotion: when `dc01` becomes a DC,
its local Administrator becomes the domain Administrator with the same password.

### `group_vars/domain_controllers.yml`

```yaml
lab_dc_ip: "10.10.10.10"    # the DC's private IP
lab_dns_server: "10.10.10.10"  # the DC uses itself for DNS
```

### `group_vars/domain_members.yml`

```yaml
lab_dns_server: "10.10.10.10"  # members resolve through the DC
```

### `group_vars/linux_pivot.yml`

```yaml
ansible_connection: ssh
ansible_user: ubuntu                                   # AWS Ubuntu default user
ansible_ssh_private_key_file: "~/.ssh/id_rsa"          # your key (matches the EC2 key pair)
ansible_ssh_common_args: "-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null"
ansible_python_interpreter: /usr/bin/python3           # where Python is on the pivot
foothold_domain_user: "helpdesk"                        # the Stage 0 credential...
foothold_domain_password: "Helpdesk#123"                # ...written into the pivot's notes
lab_dc_ip: "10.10.10.10"
```

### `group_vars/all.yml` (applies to every host)

This is the **single source of truth** for planted content. It defines:

- `lab_flags` — a dict of stage → flag string.
- `lab_users` — a list of user dicts (name, password, groups, `ou`, and
  optionally `spns` or `no_preauth`). The vuln roles filter this list.
- `lab_groups`, `lab_ous` — groups and OUs to create.
- `lab_acl_generic_all` — which principal gets GenericAll over which group.
- `lab_dcsync_group` — which group receives replication rights.
- `lab_adcs` — the CA name, the ESC1 template name, and who may enrol.

Because roles read these variables, you change the whole lab by editing this
one file. The data structures here are consumed by loops in the roles (below).

## 5. `site.yml` — the master playbook

```yaml
- import_playbook: playbooks/01-domain-controller.yml
- import_playbook: playbooks/02-domain-join.yml
- import_playbook: playbooks/03-ad-content.yml
- import_playbook: playbooks/04-vulns.yml
- import_playbook: playbooks/05-adcs.yml
- import_playbook: playbooks/06-flags.yml
- import_playbook: playbooks/07-pivot.yml
```

`import_playbook` is **static**: at parse time Ansible splices these seven files
into one ordered list of plays, then runs them top to bottom. The order encodes
the dependencies: the DC must exist before members join, AD content before the
vulns that reference it, the domain before the CA, and so on. A syntax error in
`05` is caught before `01` runs, because imports are resolved up front.

## 6. Play 01 — baseline + promote the DC

`playbooks/01-domain-controller.yml`:

```yaml
- name: Provision the Domain Controller   # play name (shown in output)
  hosts: domain_controllers               # target pattern -> matches dc01
  gather_facts: false                     # skip the implicit fact-gathering step
  roles:
    - common_win                          # run this role's tasks first...
    - domain_controller                   # ...then this one
```

`gather_facts: false` skips the automatic "collect system info" step. It speeds
things up and this play doesn't need `ansible_facts`. `roles:` expands, in
order, into all of `common_win`'s tasks followed by all of `domain_controller`'s.

### Role `common_win` (runs on every Windows host before domain work)

`roles/common_win/defaults/main.yml` sets three toggles (lowest-precedence vars):

```yaml
common_win_disable_defender: true
common_win_disable_firewall: true
common_win_enable_rdp: true
```

`roles/common_win/tasks/main.yml`, task by task:

```yaml
- name: Set DNS server to the domain controller
  ansible.windows.win_dns_client:      # module: configure DNS client
    adapter_names: "*"                 # all network adapters
    dns_servers:
      - "{{ lab_dns_server }}"         # -> 10.10.10.10 (the DC)
  when: lab_dns_server is defined      # only run if the var exists
```
`when:` is a condition; the task is skipped if it's false. Pointing DNS at the
DC is what makes domain join work later.

```yaml
- name: Set timezone (deterministic clock for Kerberos)
  community.windows.win_timezone:
    timezone: "UTC"
```
Kerberos rejects tickets if clocks skew more than ~5 minutes, so a fixed
timezone matters.

```yaml
- name: Ensure Windows time service is running and synced
  ansible.windows.win_service:
    name: w32time
    state: started       # desired state: running
    start_mode: auto     # and set to start automatically
```
`win_service` asserts a service's state; idempotent (no change if already so).

```yaml
- name: Disable Windows Defender real-time protection (lab only)
  ansible.windows.win_shell: |
    Set-MpPreference -DisableRealtimeMonitoring $true -ErrorAction SilentlyContinue
  changed_when: false       # this command never "changes" in Ansible's eyes
  failed_when: false        # never fail the play even if it errors
  when: common_win_disable_defender | bool
```
`win_shell` runs raw PowerShell. Because a shell command can't self-report
idempotency, we pin `changed_when: false`. `| bool` casts the toggle to a real
boolean. (This only removes friction for the lab; it is not hardening.)

```yaml
- name: Turn off Windows Firewall on all profiles (lab only)
  community.windows.win_firewall:
    state: disabled
    profiles: [Domain, Private, Public]
  when: common_win_disable_firewall | bool
```

```yaml
- name: Enable Remote Desktop (for manual poking during the lab)
  ansible.windows.win_regedit:
    path: HKLM:\System\CurrentControlSet\Control\Terminal Server
    name: fDenyTSConnections
    data: 0                # 0 = allow RDP
    type: dword
  when: common_win_enable_rdp | bool
```
`win_regedit` sets a registry value idempotently.

```yaml
- name: Allow RDP through (firewall is off in lab, but keep rule consistent)
  community.windows.win_firewall_rule:
    name: "Remote Desktop"
    localport: 3389
    action: allow
    direction: in
    protocol: tcp
    enabled: true
    state: present
  when: common_win_enable_rdp | bool
  failed_when: false
```

### Role `domain_controller` (promote dc01)

`roles/domain_controller/tasks/main.yml`:

```yaml
- name: Set a known local Administrator password before promotion
  ansible.windows.win_user:
    name: Administrator
    password: "{{ lab_domain_admin_password }}"
    state: present
  no_log: true          # redact args/results from output (it's a password)
```
`no_log: true` keeps the password out of logs. `win_user` manages a local
account idempotently.

```yaml
- name: Install AD DS + management tools
  ansible.windows.win_feature:
    name: [AD-Domain-Services, RSAT-AD-PowerShell, RSAT-AD-AdminCenter, RSAT-ADDS-Tools]
    include_management_tools: true
    state: present
  register: adds_feature   # capture the result into a variable
```
`win_feature` installs Windows roles/features. `register:` stores the result
dict (`changed`, `reboot_required`, etc.) as `adds_feature` for later use.

```yaml
- name: Create the new forest / promote to first DC
  microsoft.ad.domain:
    dns_domain_name: "{{ lab_domain_name }}"
    domain_netbios_name: "{{ lab_domain_netbios }}"
    safe_mode_password: "{{ lab_safe_mode_password }}"
    domain_mode: "{{ lab_forest_mode }}"
    forest_mode: "{{ lab_forest_mode }}"
    install_dns: "{{ dc_install_dns | bool }}"
    reboot: true          # reboot + reconnect automatically inside the task
  register: domain_promote
```
This is the big one. `microsoft.ad.domain` promotes the host to the first DC of
a new forest. `reboot: true` makes the module trigger the required reboot, then
wait for WinRM and reconnect, all within this single task. Idempotent: if the
domain already exists it reports `ok`.

```yaml
- name: Wait for AD web services / LDAP to answer after promotion
  ansible.windows.win_shell: |
    $ErrorActionPreference = 'Stop'
    Import-Module ActiveDirectory
    Get-ADDomain "{{ lab_domain_name }}" | Select-Object -ExpandProperty DNSRoot
  register: ad_ready
  until: ad_ready is succeeded   # retry until this succeeds...
  retries: 30                    # ...up to 30 times...
  delay: 20                      # ...waiting 20s between tries (=10 min max)
  changed_when: false            # a read-only check never "changes"
```
The `until/retries/delay` trio is the idiomatic "wait for a service to be
ready" loop. It polls LDAP until Active Directory finishes coming up after the
reboot.

```yaml
- name: Show the domain is up
  ansible.builtin.debug:
    msg: "Domain {{ ad_ready.stdout | trim }} is online on {{ inventory_hostname }}."
```
`debug` prints on the control node. `ad_ready.stdout` is the value captured two
tasks earlier; `| trim` strips whitespace; `inventory_hostname` is the current
host's name (`dc01`).

There is also `roles/domain_controller/handlers/main.yml` with a `reboot dc`
handler. Handlers run only if a task `notify:`s them, once, at the play's end.

## 7. Play 02 — join the members

`playbooks/02-domain-join.yml` targets `domain_members` (srv01, ws01) and runs
`common_win` then `domain_member`.

`roles/domain_member/tasks/main.yml`:

```yaml
- name: Wait until the domain is resolvable from this member
  ansible.windows.win_shell: |
    Resolve-DnsName -Name "{{ lab_domain_name }}" -Type A -ErrorAction Stop | Out-Null
    "ok"
  register: dns_ok
  until: dns_ok is succeeded
  retries: 30
  delay: 15
  changed_when: false
```
Same wait pattern: don't try to join until the member can resolve `vuln.local`
via the DC's DNS.

```yaml
- name: Join the domain
  microsoft.ad.membership:
    dns_domain_name: "{{ lab_domain_name }}"
    domain_admin_user: "{{ lab_domain_admin_user }}"
    domain_admin_password: "{{ lab_domain_admin_password }}"
    domain_ou_path: "{{ member_target_ou | default(omit, true) }}"
    state: domain          # desired state: joined to the domain
    reboot: true           # reboot + reconnect within the task
  register: domain_join
```
`microsoft.ad.membership` joins the machine to the domain using domain-admin
credentials, then reboots. `default(omit, true)` means: if `member_target_ou`
is empty, omit the parameter entirely (let AD use the default Computers
container). `omit` is a special value that removes an argument.

```yaml
- name: Confirm domain membership
  ansible.windows.win_shell: (Get-CimInstance Win32_ComputerSystem).Domain
  register: joined_domain
  changed_when: false

- name: Report membership
  ansible.builtin.debug:
    msg: "{{ inventory_hostname }} is joined to {{ joined_domain.stdout | trim }}."
```
A read-only confirmation and a printed summary.

`roles/domain_member/defaults/main.yml` just sets `member_target_ou: ""`, the
default the join task falls back on.

## 8. Play 03 — create AD content

`playbooks/03-ad-content.yml` runs on `domain_controllers` and applies the
`ad_content` role. This is the best place to learn **loops**.

`roles/ad_content/defaults/main.yml` aliases the shared data into role vars:

```yaml
ad_content_users:  "{{ lab_users }}"    # from group_vars/all.yml
ad_content_groups: "{{ lab_groups }}"
ad_content_ous:    "{{ lab_ous }}"
```

`roles/ad_content/tasks/main.yml`:

```yaml
- name: Create organizational units
  microsoft.ad.ou:
    name: "{{ item }}"                 # 'item' is the current loop element
    path: "{{ lab_domain_dn }}"        # create under DC=vuln,DC=local
    state: present
  loop: "{{ ad_content_ous }}"         # run this task once per OU name
```
`loop:` repeats the task for each element of a list; the current element is
`item`. `microsoft.ad.ou` creates an OU idempotently.

```yaml
- name: Create groups
  microsoft.ad.group:
    name: "{{ item.name }}"                    # item is a dict here
    scope: "{{ item.scope | default('global') }}"  # default if key missing
    category: security
    path: "OU={{ item.ou }},{{ lab_domain_dn }}"
    description: "{{ item.description | default(omit) }}"
    state: present
  loop: "{{ ad_content_groups }}"
  loop_control:
    label: "{{ item.name }}"           # print just the name, not the whole dict
```
When looping over dicts, `item.name` accesses a field. `default('global')`
supplies a fallback; `default(omit)` drops the argument if the key is absent.
`loop_control.label` cleans up the output (otherwise Ansible prints the entire
dict for each iteration).

```yaml
- name: Create users
  microsoft.ad.user:
    name: "{{ item.name }}"
    upn: "{{ item.upn }}@{{ lab_domain_name }}"
    firstname: "{{ item.display_name.split(' ')[0] | default(item.name) }}"
    display_name: "{{ item.display_name | default(item.name) }}"
    description: "{{ item.description | default(omit) }}"
    password: "{{ item.password }}"
    password_never_expires: true
    update_password: on_create        # only set the password when first created
    path: "OU={{ item.ou }},{{ lab_domain_dn }}"
    state: present
  loop: "{{ ad_content_users }}"
  loop_control:
    label: "{{ item.name }}"
  no_log: true                         # loop iterates over passwords -> redact
```
`update_password: on_create` means re-running won't overwrite a password you
changed while attacking (important for `reset-soft` semantics). `.split(' ')[0]`
is Jinja/Python: take the first word of the display name as the first name.
`no_log: true` because the loop data contains passwords.

```yaml
- name: Add each user to their declared groups
  microsoft.ad.group:
    name: "{{ item.1 }}"               # item.1 = the group name
    members:
      add:
        - "{{ item.0.name }}"          # item.0 = the user dict
    state: present
  loop: "{{ ad_content_users | subelements('groups', skip_missing=True) }}"
  loop_control:
    label: "{{ item.0.name }} -> {{ item.1 }}"
```
`subelements` is the star here. It flattens a list-of-dicts-with-a-sublist into
pairs: for each user and each entry in that user's `groups` list, you get
`(user_dict, group_name)`, exposed as `item.0` and `item.1`. `skip_missing=True`
tolerates users with no `groups` key. So one task adds every user to every group
they declare, membership defined entirely by the data in `all.yml`.

## 9. Play 04 — plant the AD vulns

`playbooks/04-vulns.yml` runs three roles on the DC: `vuln_kerberoast`,
`vuln_asrep`, `vuln_acl_dcsync`. We explain the Ansible constructs; the security
rationale is in `attack-chains.md`.

### `vuln_kerberoast`

```yaml
- name: Register SPNs on service accounts that declare them
  microsoft.ad.user:
    name: "{{ item.name }}"
    identity: "{{ item.name }}"
    spn:
      set: "{{ item.spns }}"           # set the servicePrincipalName attribute
    state: present
  loop: "{{ lab_users | selectattr('spns', 'defined') | list }}"
  loop_control:
    label: "{{ item.name }} : {{ item.spns | join(', ') }}"
```
The key idea is the **filtered loop**: `lab_users | selectattr('spns',
'defined') | list` keeps only users that have an `spns` key. So the role acts on
whatever the data says, no hard-coded names. `spn.set` writes that attribute via
the `microsoft.ad.user` module (idempotent).

```yaml
- name: Verify the SPNs are visible in the directory
  ansible.windows.win_shell: |
    Import-Module ActiveDirectory
    Get-ADUser -LDAPFilter '(servicePrincipalName=*)' -Properties servicePrincipalName |
      Select-Object SamAccountName,@{n='spn';e={$_.servicePrincipalName -join ';'}} |
      ConvertTo-Json -Compress
  register: spn_check
  changed_when: false
```
A read-only verification via PowerShell, captured into `spn_check`.
`changed_when: false` since it only reads.

```yaml
- name: Show Kerberoastable accounts
  ansible.builtin.debug:
    msg: "Kerberoastable: {{ spn_check.stdout | trim }}"
```

### `vuln_asrep`

```yaml
- name: Disable Kerberos pre-authentication on flagged accounts
  ansible.windows.win_shell: |
    Import-Module ActiveDirectory
    Set-ADAccountControl -Identity "{{ item.name }}" -DoesNotRequirePreAuth $true
    (Get-ADUser -Identity "{{ item.name }}" -Properties DoesNotRequirePreAuth).DoesNotRequirePreAuth
  register: preauth
  changed_when: true
  loop: "{{ lab_users | selectattr('no_preauth', 'defined') | selectattr('no_preauth') | list }}"
  loop_control:
    label: "{{ item.name }}"
```
Two chained `selectattr` filters: first keep users that *have* the `no_preauth`
key, then keep those whose value is truthy. There's no dedicated module for this
attribute, so a `win_shell` runs the PowerShell cmdlet. `changed_when: true`
declares it a change every run (a raw command can't tell).

```yaml
- name: Show AS-REP roastable accounts
  ansible.builtin.debug:
    msg: "DoesNotRequirePreAuth set on: {{ lab_users | selectattr('no_preauth', 'defined') | selectattr('no_preauth') | map(attribute='name') | list }}"
```
`map(attribute='name')` pulls the `name` from each matching dict, giving a clean
list of account names.

### `vuln_acl_dcsync`

```yaml
- name: Resolve DN of the GenericAll target group
  ansible.windows.win_shell: |
    Import-Module ActiveDirectory
    (Get-ADGroup -Identity "{{ lab_acl_generic_all.target_group }}").DistinguishedName
  register: target_group_dn
  changed_when: false
```
Reads the group's Distinguished Name into `target_group_dn` for the next task.

```yaml
- name: Grant GenericAll on the target group to the trustee (Stage 2 misconfig)
  ansible.windows.win_shell: >-
    dsacls "{{ target_group_dn.stdout | trim }}"
    /G "{{ lab_domain_netbios }}\{{ lab_acl_generic_all.trustee }}:GA"
  register: genericall
  changed_when: "'The command completed successfully' in genericall.stdout"
```
`>-` is YAML "folded scalar": it joins the wrapped lines into one command with
single spaces (and no trailing newline), so a long `dsacls` line stays readable.
`dsacls` edits an AD object's ACL; `:GA` = GenericAll. `changed_when` here is an
**expression**: the task counts as changed only if the success string appears in
stdout. This is how you give a raw command sensible change reporting.

```yaml
- name: Grant the DCSync replication rights to the privileged group (Stage 3 misconfig)
  ansible.windows.win_shell: >-
    dsacls "{{ lab_domain_dn }}"
    /G "{{ lab_domain_netbios }}\{{ lab_dcsync_group }}:CA;{{ item }}"
  loop:
    - "Replicating Directory Changes"
    - "Replicating Directory Changes All"
  register: dcsync_grant
  changed_when: "'The command completed successfully' in dcsync_grant.stdout"
  loop_control:
    label: "{{ lab_dcsync_group }} <- {{ item }}"
```
A `loop:` over the two replication rights, granting each with `dsacls`
(`:CA;<right>` = a specific control/extended right). During a loop, `changed_when`
is evaluated per iteration against that iteration's result.

```yaml
- name: Verify replication rights landed on the domain head
  ansible.windows.win_shell: |
    dsacls "{{ lab_domain_dn }}" | Select-String -SimpleMatch "{{ lab_dcsync_group }}"
  register: dcsync_verify
  changed_when: false
  failed_when: false

- name: Show DCSync grant
  ansible.builtin.debug:
    msg: "{{ dcsync_verify.stdout_lines | default(['(dsacls output not captured - verify manually)']) }}"
```
`stdout_lines` is the registered output split into a list of lines; `default([...])`
provides a friendly message if it's empty.

## 10. Play 05 — ADCS + ESC1

`playbooks/05-adcs.yml` runs on `srv01`: `adcs_ca` then `vuln_adcs_esc1`.

### `adcs_ca`

`roles/adcs_ca/defaults/main.yml` sets CA parameters (type, key length, hash,
validity). The tasks install the AD CS feature (`win_feature`), then configure
the Enterprise Root CA with a `win_shell` calling `Install-AdcsCertificationAuthority`.
That configure task uses `changed_when`/`failed_when` expressions to treat an
"already installed" CA as success rather than an error (idempotency for a
command that isn't naturally idempotent), and `args: executable: powershell.exe`
forces the shell to be PowerShell.

### `vuln_adcs_esc1`

This role shows **templating a file onto the target**:

```yaml
- name: Render the ESC1 template-creation script
  ansible.windows.win_template:
    src: New-ESC1Template.ps1.j2       # a Jinja template in the role's templates/
    dest: C:\Windows\Temp\New-ESC1Template.ps1
```
`win_template` renders a `.j2` file through Jinja on the control node (filling in
`{{ lab_adcs.* }}` values), then copies the result to the Windows host. The
companion `Publish-ESC1Template.ps1.j2` is rendered the same way.

```yaml
- name: Create the vulnerable ESC1 certificate template in AD
  ansible.windows.win_shell: powershell.exe -ExecutionPolicy Bypass -File C:\Windows\Temp\New-ESC1Template.ps1
  register: esc1_create
  changed_when: "'created' in esc1_create.stdout"
```
Runs the rendered script. The script prints `created` or `already-exists`, and
`changed_when` keys off that word, so re-runs show `ok` instead of `changed`.

```yaml
- name: Give AD a moment to replicate the new template object
  ansible.builtin.pause:
    seconds: 10
```
`pause` simply waits (here to let the new AD object settle before publishing).

```yaml
- name: Publish the ESC1 template on the CA
  ansible.windows.win_shell: powershell.exe -ExecutionPolicy Bypass -File C:\Windows\Temp\Publish-ESC1Template.ps1
  register: esc1_publish
  changed_when: "'published' == (esc1_publish.stdout | trim)"
  retries: 5
  delay: 10
  until: esc1_publish is succeeded
```
Publishing can fail until AD replication catches up, so it's wrapped in a
retry loop. The Jinja templates themselves (in the role's `templates/` folder)
are ordinary PowerShell with `{{ lab_adcs.template_name }}` etc. substituted in;
what makes the template deliberately weak is documented in `attack-chains.md`.

## 11. Play 06 — plant the flags

`playbooks/06-flags.yml` has **two plays** in one file. The first targets
`srv01`, the second `domain_controllers`. Both use the same `flags` role but
feed it different data through **play-level `vars:`**:

```yaml
- name: Plant SRV01 loot shares ...
  hosts: srv01
  gather_facts: false
  vars:
    flags_to_place:            # a list of flag definitions, consumed by the role
      - key: kerberoast        # which flag string (lookup into lab_flags)
        name: "..."            # human label written into the file
        dir: 'C:\Shares\mssql_backups'
        filename: flag.txt
        share: 'mssql_backups$'   # optional SMB share name
        principals: ["svc_mssql"] # who (besides admins) may read it
        hint: "..."               # pointer to the next stage
      - key: asrep
        ...
  roles:
    - flags
```
Defining `flags_to_place` under `vars:` overrides the role's empty default
(`flags_to_place: []`). This is the clean way to reuse one role with different
inputs per host.

`roles/flags/tasks/main.yml`:

```yaml
- name: Ensure flag directories exist
  ansible.windows.win_file:
    path: "{{ item.dir }}"
    state: directory
  loop: "{{ flags_to_place }}"
  loop_control:
    label: "{{ item.dir }}"
```
`win_file` creates a directory idempotently, once per flag.

```yaml
- name: Write flag files
  ansible.windows.win_template:
    src: flag.txt.j2
    dest: "{{ item.dir }}\\{{ item.filename }}"
  loop: "{{ flags_to_place }}"
```
Renders `flag.txt.j2` for each flag. The template reads
`{{ lab_flags[item.key] }}` (dictionary lookup by the `key` field) and lists
who can read it. Note `\\` in the `dest`: a single backslash would be a YAML/Jinja
escape, so Windows paths are doubled.

```yaml
- name: Lock down NTFS ACLs (break inheritance, grant only intended principals)
  ansible.windows.win_shell: |
    $dir = '{{ item.dir }}'
    icacls $dir /inheritance:r | Out-Null
    icacls $dir /grant:r "SYSTEM:(OI)(CI)F" | Out-Null
    icacls $dir /grant:r "BUILTIN\Administrators:(OI)(CI)F" | Out-Null
    {% for p in item.principals | default([]) %}
    icacls $dir /grant:r "{{ lab_domain_netbios }}\{{ p }}:(OI)(CI)R" | Out-Null
    {% endfor %}
    "acl-set"
  args:
    executable: powershell.exe
  loop: "{{ flags_to_place }}"
  changed_when: true
```
This shows **Jinja control flow inside a script**: `{% for p in item.principals %}
... {% endfor %}` is a Jinja loop that runs on the control node while rendering
the command, emitting one `icacls` line per allowed principal *before* the
script is sent to the host. Ansible's `loop:` (per flag) and Jinja's `{% for %}`
(per principal within a flag) are two different loops working together. `icacls`
sets NTFS permissions; `/inheritance:r` removes inherited ACEs so only the
listed principals can read the flag.

```yaml
- name: Publish SMB shares for flags that declare one
  ansible.windows.win_shell: |
    $share = '{{ item.share }}'
    if (Get-SmbShare -Name $share -ErrorAction SilentlyContinue) { "share-exists"; return }
    New-SmbShare -Name $share -Path '{{ item.dir }}' -FullAccess "BUILTIN\Administrators" | Out-Null
    {% for p in item.principals | default([]) %}
    Grant-SmbShareAccess -Name $share -AccountName "{{ lab_domain_netbios }}\{{ p }}" -AccessRight Read -Force | Out-Null
    {% endfor %}
    "share-created"
  args:
    executable: powershell.exe
  when: item.share is defined       # only for flags that set 'share'
  loop: "{{ flags_to_place }}"
  changed_when: "'share-created' in smb_share.stdout"
  register: smb_share
```
`when: item.share is defined` skips flags with no share (like the Domain-Admin
flags placed as plain files). The script is idempotent by hand: it checks
`Get-SmbShare` and returns early if the share already exists.

`roles/flags/templates/flag.txt.j2` is the file written to each location:

```jinja
{{ lab_flags[item.key] }}          # the actual flag string
...
Stage       : {{ item.name | default(item.key) }}
Host        : {{ inventory_hostname }}
Readable by : {{ (['SYSTEM', 'Administrators'] + (item.principals | default([]))) | join(', ') }}
...
{% if item.hint is defined %}
Next: {{ item.hint }}
{% endif %}
```
`{% if %}` conditionally includes the hint line; list concatenation with `+`
builds the "readable by" line; `| join(', ')` renders a list as CSV.

## 12. Play 07 — configure the pivot

`playbooks/07-pivot.yml` targets `linux_pivot` with `gather_facts: true` (Linux
facts are cheap and sometimes useful) and runs `linux_pivot`. This is the only
**Linux** play, so it uses SSH and Python modules, and introduces `become`.

`roles/linux_pivot/tasks/main.yml`:

```yaml
- name: Install base recon packages (best effort)
  ansible.builtin.apt:
    name: "{{ pivot_packages }}"     # a list from defaults/main.yml
    state: present
    update_cache: true
  become: true                       # run with sudo (root)
  register: apt_install
  failed_when: false                 # don't abort if offline
```
`apt` is the Debian/Ubuntu package module. `become: true` is privilege
escalation (sudo); installing packages needs root. `failed_when: false` keeps
the play going if there's no internet.

```yaml
- name: Install offensive Python tooling into a venv (best effort, needs internet)
  ansible.builtin.pip:
    name: "{{ pivot_pip_packages }}"
    virtualenv: "/opt/offsec-venv"
    virtualenv_command: "python3 -m venv"
    state: present
  become: true
  register: pip_install
  failed_when: false
```
`pip` installs Python packages into an isolated virtualenv.

```yaml
- name: Point resolver at the domain controller for vuln.local
  ansible.builtin.copy:
    dest: /etc/systemd/resolved.conf.d/vuln-lab.conf
    content: |
      [Resolve]
      DNS={{ lab_dc_ip | default('10.10.10.10') }}
      Domains=~{{ lab_domain_name }}
    mode: "0644"
  become: true
  register: resolved_conf
  failed_when: false
```
`copy` with inline `content:` writes a file directly (no template file needed).
The `~vuln.local` syntax is systemd-resolved "route this domain to this DNS".

```yaml
- name: Restart systemd-resolved to apply DNS
  ansible.builtin.service:
    name: systemd-resolved
    state: restarted
  become: true
  when: resolved_conf is changed      # only restart if the file actually changed
  failed_when: false
```
`when: resolved_conf is changed` is a mini "handler" pattern: only restart the
service if the previous task modified the config. `is changed` tests the
registered result.

```yaml
- name: Create the operator notes directory
  ansible.builtin.file:
    path: "/home/{{ pivot_operator_user }}/notes"
    state: directory
    owner: "{{ pivot_operator_user }}"
    group: "{{ pivot_operator_user }}"
    mode: "0700"
```
`file` manages a filesystem path (here a directory) with ownership and perms.

```yaml
- name: Drop the foothold creds + Stage 0 flag
  ansible.builtin.template:
    src: creds.txt.j2
    dest: "/home/{{ pivot_operator_user }}/notes/creds.txt"
    owner: "{{ pivot_operator_user }}"
    group: "{{ pivot_operator_user }}"
    mode: "0600"
```
`template` (the Linux counterpart of `win_template`) renders `creds.txt.j2`
(which embeds `foothold_domain_user/password` and the Stage 0 flag) and writes
it with `0600` perms. There's a second `template` task for the attacker README.

```yaml
- name: Report pivot readiness
  ansible.builtin.debug:
    msg: >-
      Pivot ready. apt={{ 'ok' if not apt_install.failed else 'skipped/offline' }},
      pip={{ 'ok' if not pip_install.failed else 'skipped/offline' }}.
      Foothold + Stage 0 flag at ~/notes/creds.txt
```
The `msg` uses a Jinja inline conditional (`X if cond else Y`) to report whether
the best-effort installs succeeded.

`roles/linux_pivot/defaults/main.yml` lists the apt/pip packages and sets
`pivot_operator_user: ubuntu`.

## 13. `reset.yml` — the soft reset

`playbooks/reset.yml` is a playbook that mixes inline `tasks:` and
`import_playbook`. First play (on the DC) tears down what an attacker may have
touched:

```yaml
- name: Purge planted AD content (users, groups, OUs) on the DC
  hosts: domain_controllers
  gather_facts: false
  tasks:                              # inline tasks (no role needed)
    - name: Remove lab users
      microsoft.ad.user:
        name: "{{ item.name }}"
        state: absent                 # 'absent' = delete it
      loop: "{{ lab_users }}"
    - name: Remove lab groups
      microsoft.ad.group:
        name: "{{ item.name }}"
        state: absent
      loop: "{{ lab_groups }}"
```
Deleting and recreating is how the reset wipes tampering (extra group members,
changed passwords). `state: absent` is the delete verb most modules share.

```yaml
    - name: Unpublish the ESC1 template from the CA
      ansible.windows.win_shell: |
        Remove-CATemplate -Name '{{ lab_adcs.template_name }}' -Force
        "ok"
      delegate_to: srv01              # run THIS task on srv01, not the DC
      changed_when: true
      failed_when: false
```
`delegate_to:` runs a single task on a different host than the play targets.
The play is aimed at the DC, but this cleanup must happen on the CA host
(`srv01`), so it's delegated there.

Then it re-plants everything by importing the same build playbooks:

```yaml
- import_playbook: 03-ad-content.yml
- import_playbook: 04-vulns.yml
- import_playbook: 05-adcs.yml
- import_playbook: 06-flags.yml
```

The final play runs on the control node itself:

```yaml
- name: Reset complete
  hosts: localhost
  gather_facts: false
  connection: local                  # don't SSH anywhere; run locally
  tasks:
    - name: Summary
      ansible.builtin.debug:
        msg: [ ... ]
```
`hosts: localhost` + `connection: local` runs on your machine with no remote
connection, useful for final messages or local-only steps.

## 14. Keyword & module glossary

**Play/role keywords**
- `hosts:` — which inventory pattern the play targets.
- `gather_facts:` — collect system facts before tasks (true/false).
- `roles:` — roles to run, in order; each expands to its `tasks/main.yml`.
- `tasks:` — inline tasks (instead of, or after, roles).
- `vars:` — variables scoped to this play (override role defaults).
- `become:` — run tasks with privilege escalation (sudo on Linux).
- `connection:` — override how to reach the host (e.g. `local`).

**Task keywords**
- `name:` — human label shown in output.
- `loop:` — repeat the task per list element (`item`).
- `loop_control: label:` — tidy the per-iteration output.
- `when:` — run only if the condition is true.
- `register:` — save the result into a variable.
- `changed_when:` / `failed_when:` — override how change/failure is decided (bool or expression).
- `until:` / `retries:` / `delay:` — retry loop until a condition holds.
- `no_log:` — redact this task's args/results (secrets).
- `delegate_to:` — run this task on a different host.
- `args: executable:` — force the shell binary for `*_shell`.
- `notify:` — trigger a handler (runs once at play end).

**Modules used here**
- `ansible.windows.win_*` — Windows: `win_feature`, `win_service`, `win_user`,
  `win_shell`, `win_template`, `win_file`, `win_regedit`, `win_dns_client`.
- `community.windows.win_*` — `win_timezone`, `win_firewall`, `win_firewall_rule`.
- `microsoft.ad.*` — AD: `domain`, `membership`, `ou`, `group`, `user`.
- `ansible.builtin.*` — generic/Linux: `apt`, `pip`, `copy`, `template`, `file`,
  `service`, `debug`, `pause`.

**Jinja bits you saw**
- `{{ x }}` — substitute a value. `{% for %}`/`{% if %}` — control flow while rendering.
- Filters: `default(...)`, `default(omit)`, `bool`, `trim`, `join(', ')`,
  `map(attribute='name')`, `selectattr('k','defined')`, `subelements('k')`,
  `split(' ')`. Filters transform values with a `|` pipe.

## 15. Running & debugging

```bash
# whole build (default inventory from ansible.cfg = inventory/hosts.ini)
ansible-playbook site.yml

# one stage only
ansible-playbook playbooks/03-ad-content.yml

# preview without changing anything
ansible-playbook site.yml --check --diff

# just one host
ansible-playbook site.yml --limit dc01

# see the exact tasks/hosts without running
ansible-playbook site.yml --list-tasks
ansible-playbook site.yml --list-hosts

# crank up detail (-v to -vvvv shows the module args and connection chatter)
ansible-playbook site.yml -vvv

# ad-hoc: run a single module without a playbook
ansible windows -m ansible.windows.win_ping
ansible dc01 -m ansible.windows.win_shell -a "whoami"
```

Reading a run: each line is `TASK [role : name]` then a per-host result of
`ok` (no change), `changed` (state modified), `skipping` (a `when:` was false),
or `failed`. A play ends with a `PLAY RECAP` tallying those per host. If a task
fails, re-run with `-vvv` and look at the module's returned `msg`/`stderr`.
Because everything is idempotent, it's safe to just fix and re-run
`ansible-playbook site.yml`.
